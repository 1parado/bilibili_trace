# Trace 产品需求文档（PRD）

- 版本：0.1
- 状态：待验证的产品定义
- 平台：Android 优先
- 首发数据源：Bilibili Android 使用场景
- 核心目标：时间管理、行为分析、学习复盘

## 1. 产品概述

Trace 不是另一套视频历史、收藏夹或关注列表，而是个人数字内容消费的“行为分析层”：把使用时段、可识别内容轨迹和用户主动记录的学习行为组织成时间线，并帮助用户回答：
- 我的时间主要花在哪里？哪些时段容易连续使用？
- 我最近实际接触的主题和创作者发生了什么变化？
- 我看过的学习内容，有多少转化成了笔记、复习或实践？
- 我的实际使用情况与自己设定的目标是否一致？

产品不预设使用时间一定是浪费，也不把观看时长等同于学习成果。

## 2. 用户与场景

### 目标用户
1. 经常使用 B 站学习编程、技术、语言或课程的用户。
2. 希望理解自己数字内容消费习惯、但不满足于简单屏幕时间统计的用户。
3. 想把视频消费和学习任务、笔记、复习联系起来的自我管理用户。

### 核心场景
- 晚间回顾：查看今天打开 B 站的时间段和会话长度。
- 周度回顾：观察主题分布与创作者接触变化。
- 学习闭环：将视频标为学习目标，记录笔记，安排复习或实践。
- 纠错：自动识别错误时，用户能修改标题、主题或时间归属。
- 权限受限：即使关闭无障碍服务，仍能使用应用级时长统计、分享补录和学习记录。

## 3. 产品目标与非目标

### 目标
- 建立可信、可解释的个人行为时间线。
- 清晰区分应用使用时长、内容可见区间与估算观看时长。
- 用数据支持用户自主制定时间目标和复盘学习过程。
- 验证用户是否愿意持续使用行为分析，而不只是查看一次报告。

### 非目标（MVP）
- 不复制 B 站历史、收藏、关注、稍后再看等已有功能。
- 不自动点赞、关注、评论、投币或操作用户账号。
- 不声称精确知道用户是否认真观看、理解或记住视频。
- 不做成瘾诊断、心理诊断或道德化的“浪费时间”评分。
- 不要求注册、云同步或付费模型服务才能使用核心功能。
- 不保证兼容 B 站所有页面、播放器和系统版本。

## 4. 产品差异化

1. **行为而非清单：** 关注行为发生的时间、节奏、主题变化及与个人目标的关系。
2. **证据可追溯：** 每个统计结果可以回溯到本地事件和明确公式。
3. **多口径时间：** 分别展示应用前台时长、识别内容可见区间、估算观看时长。
4. **兴趣变化而非简单排行榜：** 比较不同时间窗口的主题/创作者接触变化，并展示识别覆盖率。
5. **消费到学习闭环：** 将目标、笔记、复习和实践记录与内容关联。
6. **隐私优先：** 本地处理优先，无障碍识别可选，用户可更正、导出和删除。

## 5. 信息架构

- **今日：** 今日使用时长、会话、目标进度、快速记录。
- **轨迹：** 按时间排列的应用会话与识别到的内容事件。
- **洞察：** 时段分布、会话长度、主题变化、创作者接触趋势。
- **学习：** 学习目标、内容清单、笔记、复习日期、实践状态。
- **周报：** 以证据和时间范围为基础的周期总结。
- **设置与隐私：** 权限状态、识别开关、保留策略、导出、删除、免责声明。

## 6. 核心功能需求

### F1 应用使用会话
- 使用 Android UsageStatsManager 获取 B 站应用的前台使用事件。
- 将前台事件合并为使用会话，处理重复、乱序、缺失和设备重启等情况。
- 展示开始时间、结束时间、持续时长和数据完整性。
- 权限缺失时提供设置引导，不阻断手动记录和学习功能。

### F2 内容识别（实验性）
- 用户单独启用无障碍服务后，尝试读取目标应用界面中可访问的标题、创作者和内容切换。
- 每条识别结果记录来源、时间、置信度和可纠错状态。
- 不可识别时明确展示“未识别内容”，不编造标题。
- 仅在用户启用后处理目标应用的必要字段；不得采集无关页面、输入内容或私密消息。
- 识别覆盖率不足时降级为应用级会话、分享补录和手动输入。

### F3 分享补录
- 接收系统分享的 B 站链接。
- 尽可能解析分享文本中的标题/URL；解析失败仍保留原始链接供用户编辑。
- 分享事件表示“用户分享/记录了该内容”，不自动等同于实际观看。

### F4 时间线
- 以日期和会话分组呈现应用使用、识别内容、分享补录、学习记录。
- 区分自动观测与用户主动记录。
- 支持修改内容、分类、时间归属和“不是我在观看”等异常情况。
- 提供识别置信度/来源标记。

### F5 时间管理
- 展示日/周应用使用时长、会话数量、会话中位数/分布、常用时段。
- 用户可以设置自定义目标和提醒；MVP 不强制提醒。
- 目标是用户自定的参照，不把超过目标直接标为失败。
- 应用使用时长不得命名为“精确观看时长”。

### F6 行为与兴趣分析
- 基于用户确认的主题和识别内容，比较 7 天与 30 天主题接触情况。
- 统计创作者接触频率时明确说明“识别/记录到的内容”，不等同于平台完整观看记录。
- 展示识别覆盖率、未知内容比例和样本量。
- 低覆盖率或样本过少时隐藏趋势结论，或提示数据不足。

### F7 学习复盘
- 用户可将内容加入学习目标，记录简短笔记、待复习日期和实践状态。
- 状态建议：待整理、已记录、待复习、已实践、已完成。
- 学习成果依据用户记录，不根据播放时长自动推断。
- 支持按目标查看内容、笔记和完成情况。

### F8 周报与洞察
- 使用确定性规则优先生成统计与洞察。
- AI 总结（如未来启用）只能基于已计算数据和可引用证据，不可补造事实。
- 每条洞察包含时间范围、数据口径、样本量或证据来源。
- 外部模型调用必须独立授权并告知发送字段。

### F9 数据控制
- 查看数据来源和权限状态。
- 导出结构化数据（例如 JSON/CSV）。
- 删除单条记录、某个时间范围或全部个人数据。
- 关闭无障碍后停止新的内容识别，不删除用户已有数据，除非用户另行选择。
- 明确数据保留策略和备份/导出后的责任范围。

## 7. 关键用户流程

1. 首次启动 → 介绍用途与局限 → 用户选择启用应用时长统计。
2. 请求 Usage Access → 用户在系统设置中授权 → Trace 验证权限 → 开始记录应用会话。
3. 可选介绍内容识别 → 显示采集字段、用途和限制 → 用户主动启用无障碍服务。
4. 浏览今日时间线 → 修改识别错误 → 选择主题/学习目标。
5. 查看洞察 → 检查口径和样本 → 调整自己的时间目标或复习计划。
6. 随时关闭权限、导出或删除数据。

## 8. 指标与产品验证

### 北极星候选指标
每周至少完成一次“基于轨迹做出的有效复盘动作”的活跃用户数。有效动作包括修改目标、添加复习、补充笔记或主动调整计划；需在用户研究中验证定义是否有意义。

### MVP 观察指标
- 首次权限引导完成率。
- 至少 7 天内有 3 天产生有效记录的用户比例。
- 内容识别结果被用户纠正的比例。
- 周报打开率、洞察展开率及后续行动率。
- 用户关闭无障碍服务后仍继续使用核心功能的比例。
- 崩溃率、后台耗电反馈、数据缺失与重复事件率。

不把“使用时间下降”作为唯一成功标准，以免鼓励错误的道德化判断。

## 9. MVP 验收标准（待实测）

以下为试验目标，不代表当前能力：
- 应用级日使用时长与系统设置页面的差异目标不超过 5%（排除系统定义差异和测试误差后评估）。
- 对预先标注的测试样本，内容切换识别覆盖率目标 ≥70%。
- 在成功识别的样本中，标题/创作者字段准确率目标 ≥95%。
- 重复事件率目标 ≤2%。
- 每个统计数字均能说明计算口径并追溯到本地数据。
- 关闭无障碍权限后，应用级统计、分享补录和学习记录仍可使用。
- 用户能够导出并彻底删除应用内保存的数据。

## 10. 风险与待决事项

- Android 后台事件的可用性和系统版本差异需要实机验证。
- 无障碍服务读取能力受应用 UI、WebView、播放器、版本和无障碍节点暴露程度影响。
- Google Play 对 Accessibility API 的政策与声明要求可能影响上架；必须在发布前核对最新政策。
- B 站页面/接口可能变化；不得把非官方接口当作稳定承诺。
- 首版最低 Android 版本、是否上架 Play、是否支持国内应用分发，需要用户研究后决定。
