# 开发路线图与验收标准

## 阶段 0：项目骨架（1–2 天）
- 建立 Android Studio / Gradle 项目。
- 配置 Kotlin、Compose、Room、测试框架和静态检查。
- 定义包结构、时间语义、错误状态和隐私原则。
- 建立 CI（至少构建与单元测试）。
- 验收：可构建、可运行；README 明确环境要求和运行步骤。

## 阶段 1：应用级使用统计（第 1 周）
- 实现 Usage Access 权限状态与引导。
- 实现 UsageStats 事件查询、规范化、去重和会话切分。
- Room 保存事件和会话。
- Compose 显示今日统计与时间线。
- 处理权限撤销、无数据、设备重启和部分会话。
- 验收：有单元测试；至少在开发者设备上与系统统计对照；不宣称精确视频观看时长。

## 阶段 2：分享补录与内容管理（第 2 周）
- 接收系统分享文本/URL。
- 规范化 B 站视频链接，解析失败时允许手动编辑。
- 建立内容实体、主题标签、创作者字段和纠错流程。
- 支持将内容关联到学习目标。
- 验收：分享记录与自动识别事件在数据模型中明确区分；重复分享可控；删除行为完整。

## 阶段 3：内容识别技术验证（第 2–3 周，可并行）
- 创建可选 AccessibilityService 原型。
- 提供明确披露、独立启用和撤销入口。
- 只识别白名单目标应用中必要的标题/创作者候选。
- 生成带来源、置信度和识别版本的事件。
- 建立人工标注样本与测试矩阵。
- 验收：有实测覆盖率、字段准确率、重复率和设备范围报告；未达标则保持实验性，不影响基础功能。

## 阶段 4：时间与兴趣分析（第 3 周）
- 实现时段分布、会话统计、主题趋势和识别覆盖情况。
- 处理跨午夜、时区、区间重叠和样本不足。
- 提供指标定义与明细追溯。
- 验收：公式与边界条件有单元测试；无数据、零值、未授权和部分数据有不同 UI 状态。

## 阶段 5：学习复盘与周报（第 4 周）
- 学习目标、笔记、待复习、实践状态。
- 使用确定性规则生成周报。
- 周报中的每条结论可关联指标和时间范围。
- 验收：学习状态来自用户操作；不会从观看时长推断知识掌握；报告不生成无证据结论。

## 阶段 6：小规模试点
- 邀请 10–15 位自愿用户进行两周试点。
- 评估权限完成率、持续使用、纠错成本、报告行动率、耗电和稳定性。
- 依据结果缩小范围或决定是否开发云同步/AI 分析。
- 验收：形成书面继续/缩小/暂停决定；不以主观好评代替行为证据。

## 发布前清单
- [ ] 无障碍服务为可选功能，有清楚披露和关闭方式。
- [ ] Usage Access 缺失时有可理解的降级状态。
- [ ] 不收集 Cookie、密码、私信或无关屏幕文本。
- [ ] 本地数据可以导出和删除。
- [ ] 时间指标名称准确区分应用使用与内容曝光。
- [ ] 主要指标有公式和测试。
- [ ] 在目标 Android 版本和实际设备上完成测试。
- [ ] 核对目标应用商店的最新权限政策、隐私披露与数据安全要求。
- [ ] README 说明当前支持范围、限制和已验证情况。
