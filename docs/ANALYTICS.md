# 分析指标与洞察规则

## 1. 总原则

1. 每个指标必须有名称、公式、时间范围、时区、数据来源和定义版本。
2. 将观测事实、确定性计算、模型生成的解释分开。
3. 样本不足或采集覆盖率低时，显示“数据不足”，不要强行生成趋势。
4. 不将观看时间等同于注意力、理解、学习成果或“浪费”。
5. 用户能从每条洞察跳转到支持该结论的时间线记录或汇总明细。

## 2. 时间指标

### 应用前台时长
对所选日期范围内目标应用的有效前台区间求并集后计算总长度：

`appForegroundMs = duration(union(validForegroundIntervals))`

- 先合并重叠区间，再求总和。
- 明确区间不完整时，显示部分数据标记。
- 不将查询窗口外的时间计入。
- 与系统设置统计可能因系统口径不同存在差异，应在验证阶段解释差异。

### 会话数
按定义版本中的 sessionization 规则得到的会话数量。必须在 UI/文档中说明短间隔是否合并。

### 会话时长分布
建议同时提供中位数、分位数和分布，而不是只给平均值。样本过少时隐藏分位数或标记低样本量。

### 使用时段分布
按用户本地时区将有效前台区间拆分到小时/时段。跨小时、跨日区间必须切分，不能把整段都归到开始时间所在小时。

### 目标差值
`difference = observedDuration - userDefinedTarget`
这是与用户自设目标的差值，不是“失败分”或健康评价。

## 3. 内容识别与覆盖率

建议展示：
- 被识别的内容变化次数。
- 未识别内容区间数/占比。
- 成功识别字段中的用户纠错比例。
- 每种采集来源的贡献。
- 有效样本数和识别版本。

覆盖率应按可人工标注的测试区间定义。真实用户场景中如果没有完整真值，不得声称测得了真实识别率，只能展示“识别到的内容占比”等操作性指标。

## 4. 主题趋势

- 主题由用户手动选择或通过明确标记的分类器候选得到。
- 比较 7 天与 30 天时，展示两段时间内的样本数和识别覆盖情况。
- 同时报告内容数和估算曝光区间，避免单一长区间主导主题比例。
- 对少量样本、未知主题比例过高或两个时间窗口覆盖差异过大的情况，不输出确定性趋势。
- “最近更关注 X”应改为更谨慎的描述，例如“在已记录内容中，X 类占比有所上升”。

## 5. 创作者接触

- 统计的是 Trace 识别或用户记录到的创作者，不是平台完整观看清单。
- 同一内容的重复识别应合并为一次内容接触事件，但不同时间段的再次观看可以保留。
- 如果没有可靠且获授权的关注状态来源，不展示“看过但未关注”对比。
- 对同名创作者使用平台 ID 或规范化主页链接消歧。

## 6. 学习复盘指标

可以计算：
- 添加学习目标的内容数。
- 已产生笔记的内容比例。
- 到期复习完成率（只对已设置复习日期的记录计算）。
- 已标记实践/完成的任务数。
- 从记录到复习/实践的时间间隔。

这些指标只描述用户记录的学习活动，不应表述为知识掌握率或学习效率，除非另有独立、有效的测量方式。

## 7. 周报生成

建议结构：
1. 本周使用概览（明确系统统计口径）。
2. 时段/会话变化（展示比较窗口）。
3. 内容主题变化（显示识别覆盖率）。
4. 学习记录进度（笔记、复习、实践）。
5. 一项可执行的小建议（可选，用户自主决定）。
6. 数据质量说明。

AI 仅可对确定性聚合结果进行语言组织。每条结论需带 evidence IDs 或聚合指标键。模型输出要经过结构校验；无法映射到证据的句子应丢弃或标为待确认。默认使用本地规则，不将原始行为数据发送到远程模型。

## 8. 质量门槛

- 指标公式有单元测试。
- 跨午夜、重叠区间、重复事件、缺失边界和时区变化均有测试。
- 所有报告注明统计窗口、定义版本和数据质量。
- 数据不足时不使用空值冒充 0；区分“零事件”“未授权”“无数据”和“部分采集”。
